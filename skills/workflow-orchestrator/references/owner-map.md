# Workflow Owner Map

Use this file as the first routing layer before opening deeper workflow docs.

## Owner workflow quick map

- new or revised Technique -> `technique-workflow`
- authored Technique needs simulator coverage -> `simulation-port-workflow`
- authority change needs publication synchronization -> `core-sync-workflow`
- species-wide inventory / identity / backlog review -> `species-audit-workflow`
- repeated family grammar and inheritance work -> `status-family-workflow`
- upstream doctrinal contradiction or taxonomy problem -> `authority-revision-workflow`
- unresolved cross-subsystem blocker -> `dependency-review-workflow`
- tuning or evidence-driven power/cost review -> `balance-review-workflow`
- large retroactive migration or cleanup -> `batch-refactor-workflow`
