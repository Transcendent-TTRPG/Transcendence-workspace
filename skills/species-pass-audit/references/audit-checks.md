# Species Audit Checks

Every species audit should leave explicit status and next steps.

## Inventory checks

- authored inventory explicit
- structured data inventory explicit
- simulation inventory explicit when relevant
- publication inventory explicit when relevant

## Identity checks

- species identity strengths explicit
- identity drift or bleed explicit
- redundancy vs distinction explicit

## Coverage checks

- sim-defined state explicit
- runtime-supported state explicit
- backlog of unported items explicit

## Blocker checks

- blockers are classified rather than implied
- upstream vs local blockers are separated

## Closure checks

- audit scope explicit
- audit conclusion explicit
- prioritized next steps explicit
- change impact explicit when project state was updated
