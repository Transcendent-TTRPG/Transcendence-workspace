# Technique Run Checkpoints

Every Technique run should be recoverable from these checkpoints.

## Intake

- species or family identified
- exact Technique identified
- objective of the run stated
- current authority / simulation / publication state identified
- mandatory sources listed

## Species framing

- species fit stated
- world origin stated
- non-goals stated when relevant
- primary and secondary interaction surfaces named

## Mechanical framing

- category stated
- roll model stated
- source competency stated
- effect family stated
- duration / expiry / restrictions stated
- rhythm / attrition stated

## Dependency framing

- upstream dependencies mapped
- downstream dependencies mapped
- linked files identified
- blocker status identified

## Balance framing

- cost sanity check recorded
- comparison set chosen
- pressure / frequency / counterplay noted

## Simulation framing

- surface reuse vs new runtime decided
- runtime gap classified
- policy/scenario/question implications noted

## Editorial framing

- inheritance vs duplication checked
- terminology checked
- publication impact checked

## Integration and validation

- authority updated
- structured data updated when required
- simulator/core updates routed if needed
- validation performed or explicitly deferred with reason

## Closure

- acceptance status explicit
- pending items explicit
- change impact explicit
